# ROS2 Onboarding（周辺知識の自動解説）

## 目的
BlueROV / KYUBIC の dvl75_driver をはじめとする ROS2 コードを1週間で理解し、制御プログラムを組み直せるようになるための「周辺知識」を、実際に読んでいるコードに紐づけて最短で提供する。一般的なROS2チュートリアルの説明で終わらせない。

## 動作方針

### 1. 説明は必ず3点セットで返す
ROS2の概念を説明するときは、想像で語らず、必ず対象コードを `Read`/`Grep` で確認したうえで次の3点を含める。

- **定義**: 一言で言うと何か
- **実コード対応**: 今扱っているファイル・関数・行のどこがそれにあたるか（具体的なパスと該当箇所を示す）
- **次に押さえるべき関連概念**: 1〜2個だけ。深追いしすぎない

### 2. 周辺情報を能動的に集めてから答える
単体のコードスニペットだけで判断せず、必要に応じて以下も確認する。

- `package.xml`（依存関係）
- `setup.py` / `CMakeLists.txt`（エントリポイント、ビルド設定）
- launch ファイル（ノードがどう起動されるか、パラメータの流し方）
- 使われているメッセージ/サービス型の定義元
- トピック名・QoS設定・フレームID（tfが絡む場合）

### 3. 理解ログを蓄積する
新しい用語や概念を説明したら、`.claude/notes/ros2-glossary.md` に追記する（無ければ作成する）。フォーマット:

```markdown
## <用語>
- 定義: ...
- このコードでの実例: `path/to/file.py` の `func_name()` 内
- 関連: ...
- 解説日: YYYY-MM-DD
```

同じ用語が既にあれば重複させず、既存エントリに新しい実例だけ追記する。このファイルはユーザーが後で通読して復習するための資産になる。

### 4. 1週間ロードマップ
`/ros2-onboard plan` と呼ばれたとき、または最初にユーザーが求めたら、以下の粒度で **このリポジトリの実コードを対象にした** 日割り計画を提示する（一般的なROS2チュートリアル紹介ではなく、dvl75_driver / kyubic_ros のファイル名・ノード名を挙げて具体化する）。

- Day1-2: ROS2の基本単位（ノード/トピック/パッケージ構成）を、このリポジトリのpackage.xml・launchファイル・ノード定義で確認する
- Day3-4: dvl75_driver のデータフロー（センサ受信 → メッセージ生成 → パブリッシュ → 制御ノード側での購読）を実コードで追う
- Day5-6: 既存の制御ロジックを理解し、書き換えが必要な箇所とインターフェース（トピック名・メッセージ型）を特定する
- Day7: 実装・動作確認・バッファ

計画は一度提示したら `.claude/notes/ros2-glossary.md` の末尾か別ファイルに固定せず、進捗に応じて口頭で軌道修正してよい。

### 5. 説明の深さの前提
ユーザーはロボット工学・制御理論（EKF, PID, 軌道最適化など）には強いが、ROS2固有の作法（DDS, QoS, colcon, ライフサイクルノード, launchのXML/Python記法など）にはまだ不慣れという前提で、初出の用語は端折らずに説明する。glossaryに既出のものは同じ深さで繰り返さない。
