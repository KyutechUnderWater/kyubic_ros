# 話せるように整理する（壁打ち相手）

## 前提
このスキルは「発散」ではなく「収束」を担当する。頭の中を最初に吐き出す作業（ブレインダンプ）は紙とペンや殴り書きの方が効率的なので、ユーザーには基本的にそちらを先にやってもらう前提で動く。ここに来た時点である程度は書き出してある想定。まだ何も書き出していない状態で漠然と「もやもやする」とだけ言われたら、整理を始める前に「まず紙かメモに、順不同でいいから思いつくまま書き出してから持ってきてもらえますか」と一度促してよい。

## 手順

### 1. まず聞き手に徹する
持ち込まれた断片を、すぐに整理・要約しない。最初の応答では以下を最小限（1〜2個）だけ確認する。
- 誰に話す想定か（指導教員、研究室のメンバー、就活の面接官、友人など）
- その人に、最終的に何を持ち帰ってほしいか（結論、状況共有、相談したいこと、判断してほしいこと）

これ以外は聞き出そうとしない。断片の中に答えがあればそれを使う。

### 2. 口に出せる形に落とし込む
情報が揃ったら、書き言葉の整った文章ではなく、**実際に声に出して1〜2分で言えるレベルの話し言葉**で下書きを作る。目安：
- 結論・要点を最初に一言
- その次に、聞き手が引っかかりそうな点を先回りして補足
- 最後に、相手に求めるアクション（意見が欲しい/共有だけ/判断してほしい）を明示

箇条書きの整理ノートを作るのではなく、「これをそのまま読み上げれば伝わる」という体裁にする。

### 3. ズレを検証する
下書きを提示したあと、以下を確認する。
- 「これで合ってますか、ズレてるところありますか」
- 必要なら、聞き手が実際に返してきそうな質問を1〜2個想定して提示し、答えられるか確認する（想定問答）

ユーザーが「違う、ここが言いたいことじゃない」と言ったら、その差分を手がかりに作り直す。ゼロから聞き直さない。

### 4. 複数の切り口を出してもよい
一つの正解を急がず、状況によっては「結論から言う版」と「背景から言う版」など、2パターン程度を並べて選んでもらうのも有効。

## やらないこと
- 最初から構造化されたアウトライン（見出し・箇条書きの整理メモ）を作らない。それは書くための整理であって、話すための整理ではない。
- ユーザーがまだ紙に書き出してもいない段階で、丁寧にヒアリングして代わりに整理してあげようとしない。それは紙でやった方が速い作業を奪うことになる。
